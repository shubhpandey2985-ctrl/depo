# DEEPTECH — DESIGN SYSTEM & VISUAL SPECIFICATION

Product:
DeepTech

Brand subtitle:
innovation centre

Purpose:
Define the complete visual language for the DeepTech web application.

This document controls the visual design, typography, color, spacing, components, interaction states, layouts and overall aesthetic.

The final product must feel like a distinctive modern innovation-centre product — not a generic SaaS dashboard, college ERP, inventory CRUD application, Bootstrap template or AI-generated admin panel.

==================================================
1. CORE VISUAL DIRECTION
==================================================

DeepTech should feel:

Modern
Technological
Confident
Creative
Intelligent
Organized
Premium
Approachable
Startup-oriented

The visual identity should combine:

TECHNOLOGY
+
INNOVATION
+
EDITORIAL DESIGN
+
PRODUCT USABILITY

The interface should have a strong visual personality without becoming complicated.

The design should feel intentionally art-directed.

Avoid the visual language of:

- generic SaaS dashboards
- enterprise ERP software
- college management portals
- spreadsheet applications
- generic admin templates
- excessive glassmorphism
- excessive gradients
- excessive rounded cards
- "AI startup" clichés
- purple-everywhere interfaces

==================================================
2. BRAND IDENTITY
==================================================

Primary brand name:

DeepTech

Secondary brand text:

innovation centre

Brand lockup:

DeepTech
innovation centre

The word "DeepTech" should be visually dominant.

"innovation centre" should appear underneath or beside it depending on context, but must remain significantly smaller.

The brand should feel sophisticated rather than corporate.

==================================================
3. TYPOGRAPHY
==================================================

Primary display font:

Grand Hotel

Primary functional font:

Lato

These two fonts form the signature typography system of DeepTech.

--------------------------------------------------
GRAND HOTEL
--------------------------------------------------

Use Grand Hotel selectively.

Primary uses:

- DeepTech wordmark
- major hero statements
- selected large editorial headings
- short expressive phrases
- visual section introductions

Examples:

DeepTech

Resources that move ideas.

Build.
Experiment.
Innovate.

Do not use Grand Hotel for:

- body paragraphs
- tables
- navigation
- forms
- buttons
- filters
- metadata
- dense UI
- long headings

Grand Hotel should feel special because it is used sparingly.

--------------------------------------------------
LATO
--------------------------------------------------

Use Lato for the functional interface.

Use it for:

- navigation
- buttons
- labels
- body text
- tables
- forms
- search
- filters
- dropdowns
- badges
- notifications
- numbers
- metadata
- descriptions
- analytics

Lato should provide clarity and usability.

==================================================
7. COLOR PHILOSOPHY
==================================================

The interface should NOT look colorful simply for the sake of being colorful.

Color should communicate hierarchy and meaning.

Use large neutral surfaces.

Use accent colors as moments of emphasis.

Example:

Neutral page
+
deep typography
+
one strong violet CTA
+
small mint availability badge

This should be preferred over:

purple background
+
purple cards
+
purple buttons
+
purple chart
+
purple icons

==================================================
8. BACKGROUNDS
==================================================

Primary application background:

#F7F8FC

Use white surfaces for important content.

Example:

Page background
#F7F8FC

Content surface
#FFFFFF

Secondary surface
#EEEAFE / #E7F4FF

Use subtle contrast rather than heavy shadows.

==================================================
9. BORDERS
==================================================

Default border:

#E5E7EB

Border width:

1px

Use borders sparingly.

Borders should establish structure without making the UI look like a spreadsheet.

Avoid heavy outlines around every element.

==================================================
10. BORDER RADIUS
==================================================

Use a controlled radius system.

Small:

8px

Medium:

12px

Large:

16px

Feature surfaces:

20–24px

Do not make every component extremely rounded.

Avoid the "everything is a pill" aesthetic.

Pills should primarily be used for:

- status
- tags
- filters
- compact categories

==================================================
11. SHADOWS
==================================================

Use subtle shadows only where elevation is necessary.

Preferred:

soft
low-opacity
large blur
minimal visual weight

Avoid:

dark shadows
heavy floating cards
multiple layers of shadows

The design should primarily rely on:

spacing
contrast
typography
surface changes

rather than shadows.

==================================================
12. GRID SYSTEM
==================================================

Use a responsive 12-column desktop grid.

Desktop:

1440px primary design target.

Suggested:

Max content width:
1280–1360px

Page horizontal padding:

32–64px depending on viewport.

Tablet:

24–32px

Mobile:

16–20px

Use consistent alignment.

Do not randomly place elements.

Asymmetry is allowed when intentional.

==================================================
13. LAYOUT PHILOSOPHY
==================================================

Avoid rigid dashboard grids.

Use a mixture of:

- full-width sections
- asymmetric cards
- editorial blocks
- compact information groups
- large feature surfaces
- offset elements
- whitespace

Example dashboard composition:

Large editorial introduction
+
small metric cluster
+
large inventory overview
+
activity panel
+
returns panel

rather than:

4 identical cards
+
large table
+
chart

==================================================
14. WHITESPACE
==================================================

Whitespace is a major part of the DeepTech identity.

Do not attempt to fill every empty area.

Use:

large section gaps
generous page margins
clear card padding
breathing room around headings

Whitespace should make the product feel premium.

18. BUTTON SHAPE
==================================================

Use moderate corner radius.

Buttons should feel:

solid
precise
confident

Avoid excessively pill-shaped buttons unless used intentionally for a special CTA.

==================================================
19. INPUT SYSTEM
==================================================

Inputs should be:

clean
spacious
readable
quiet

Default:

white background
1px border
12px radius

States:

Default
Hover
Focus
Filled
Error
Disabled

Focus state should use the DeepTech accent.

Never remove the focus state.

==================================================
20. SEARCH
==================================================

Search should be visually prominent where discovery is the main task.

Inventory search example:

Search resources...

Include a search icon.

Allow clear search.

Use a wide search field on desktop.

On mobile, search should become full-width.

==================================================
21. FILTER SYSTEM
==================================================

Filters should not dominate the interface.

Inventory filters:

Name
Category

Quantity / Availability

Use:

dropdowns

compact filter buttons

Active filters should be visually distinguishable.

Provide:

Clear filters

Do not hide important filtering controls inside unnecessarily complicated UI.

27. DASHBOARD METRICS
==================================================

Dashboard statistics should feel integrated into the composition.

Avoid four identical giant metric cards.

Instead vary hierarchy.

Example:

Total items

Secondary metrics should remain compact.

==================================================
30. ISSUE FLOW VISUAL DESIGN
==================================================

Issue workflow should use a clear step indicator.

Example:

01
Select item

02
Recipient

03
Confirm

The active step should use the primary accent.

Completed steps should be visually quieter.

The form should remain focused.

Do not place unrelated information around the workflow.

32. SUCCESS STATE
==================================================

Success screens should feel satisfying but restrained.

Example:

Resource issued.

Use:

success icon
clear confirmation
summary
next actions

Primary:

View issue record

Secondary:

Issue another resource

Do not use giant celebratory animations.

==================================================
33. HISTORY DESIGN
==================================================

History should feel like a reliable record.

Use:

clear table
filters
status badges
timestamps

Important information:

Resource
Person
Profession
Issued
Return date
Status

History should be easy to scan.

==================================================
34. PEOPLE DESIGN
==================================================

People should feel like part of the same ecosystem.

Use:

person name
profession
active items
last activity
status

Avoid overloading the screen with account-management controls.

==================================================
35. INSIGHTS DESIGN
==================================================

Analytics should be:

minimal
informative
visual
readable

Use a small number of meaningful visualizations.

Prefer:

large insight statement
+
supporting chart
+
key metric

rather than many tiny charts.

==================================================
36. MODALS
==================================================

Use modals only when they improve focus.

Examples:

Delete confirmation
Quick resource preview
Important confirmation

Avoid using modals for entire workflows when a dedicated page or sheet would provide better usability.

==================================================
37. DRAWERS
==================================================

Use drawers for:

Mobile filters
Quick details
Contextual actions

Drawers should have:

clear title
close action
appropriate spacing

==================================================
38. TOASTS
==================================================

Toasts should be:

small
clear
non-intrusive

Examples:

Resource added successfully.

Resource issued successfully.

Resource returned successfully.

Do not show excessive notifications.

==================================================
39. ICONOGRAPHY
==================================================

Use one consistent icon family.

Icons should generally be:

simple
minimal
modern
consistent in stroke weight

Suggested visual style:

outline icons

Do not mix:

filled icons
3D icons
emoji
random SVG styles

Use icons to reinforce meaning, not decorate empty space.

==================================================
40. ILLUSTRATION / VISUAL LANGUAGE
==================================================

If illustrations are used, they should feel:

technical
abstract
minimal
editorial

Possible visual themes:

circuits
nodes
systems
hardware
network structures
geometric forms

Avoid generic stock illustrations.

Avoid cliché AI illustrations.

==================================================
41. MOTION
==================================================

Motion should be subtle and functional.

Recommended:

150–250ms

Use easing that feels natural.

Use motion for:

hover
focus
dropdowns
modals
navigation
filter changes
success states

Avoid:

bouncing UI
constant floating
large page transitions
excessive parallax
attention-seeking animation

==================================================
42. RESPONSIVE DESIGN
==================================================

Desktop is the primary experience.

At tablet:

Reduce columns.
Compress navigation.
Maintain hierarchy.

At mobile:

Stack content.
Collapse navigation.
Convert filters into a sheet/drawer.
Convert complex tables into cards where appropriate.
Make primary actions easy to reach.

Do not simply scale desktop down.

==================================================
43. MOBILE NAVIGATION
==================================================

Mobile navigation should remain simple.

Use:

hamburger / menu
or
bottom navigation where appropriate.

Do not display the full desktop sidebar on a small screen.

==================================================
44. ACCESSIBILITY
==================================================

Maintain:

WCAG-conscious contrast
visible focus
keyboard navigation
clear labels
semantic controls
readable typography

Status must never depend solely on color.

Example:

Available

rather than:

green dot only

==================================================
46. VISUAL RHYTHM
==================================================

Do not make every section visually equal.

Create rhythm through:

Large heading
↓
Small supporting text
↓
Large whitespace
↓
Important content
↓
Compact metadata
↓
Secondary content

Use scale variation intentionally.

==================================================
47. PREMIUM PRODUCT RULE
==================================================

Premium does NOT mean:

more gradients
more shadows
more glass
more animations
more colors

Premium means:

better spacing
better typography
better hierarchy
better composition
better consistency
better interaction design

==================================================
48. STARTUP PERSONALITY
==================================================

DeepTech should have a recognizable personality.

The strongest visual signatures should be:

1. Grand Hotel + Lato typography pairing.
2. Editorial/asymmetric layouts.
3. Restrained but confident color accents.
4. Generous whitespace.
5. Strong information hierarchy.
6. Clean technical visual language.
7. Carefully designed interactions.

==================================================

==================================================

DO NOT create:

❌ Generic Bootstrap dashboard
❌ Generic college ERP
❌ Generic inventory CRUD
❌ Four identical metric cards everywhere
❌ Excessive rounded rectangles
❌ Excessive glassmorphism
❌ Excessive purple
❌ Giant gradient blobs
❌ Random illustrations
❌ Random stock photos
❌ Excessive shadows
❌ Tiny unreadable text
❌ Overloaded dashboards
❌ Decorative charts with no meaning
❌ Excessive animations
❌ Inconsistent icon styles
❌ Every element inside a card
❌ Every button as a pill
❌ Poor mobile layouts

==================================================
50. TARGET VISUAL IMPRESSION
==================================================

When someone opens DeepTech, the immediate impression should be:

“This is a modern technology product built for an innovation centre.”

Not:

“This is a college ERP.”

Not:

“This is a generic admin dashboard.”

Not:

“This was generated from a UI template.”

==================================================
51. DESIGN REFERENCE PHILOSOPHY
==================================================

Use the principles of modern editorial product design:

Large expressive typography
+
strong grid
+
asymmetry
+
whitespace
+
subtle surfaces
+
precise interactions

The interface should feel designed rather than assembled.

==================================================
52. FINAL DESIGN PRINCIPLE
==================================================

DeepTech should be:

DISTINCTIVE
without being confusing.

MINIMAL
without being empty.

VISUAL
without being decorative.

TECHNICAL
without being intimidating.

PREMIUM
without being excessive.

STARTUP-LIKE
without becoming trendy or generic.

The final interface should feel cohesive across:

Login
Dashboard
Inventory
Resource Details
Issue Flow
Success
History
People
Insights
User Dashboard

Every screen must clearly belong to the same DeepTech design system.

FINAL RULE:

Do not design a collection of screens.

Design one coherent product.
